# 丢1帧、取第2帧实验

独立入口，原 fast_two_stage.py、two_stage.py 和公共 Camera 均未修改：

```bash
.venv/bin/python experiments/gated_model/one_flush_two_stage.py --hardware
```

加 `--serve` 后先加载依赖，再输入 `run` 测量、`quit` 退出。

只改变每次采集的读帧次数：原先丢弃4张再取第5张，本实验丢弃1张再取第2张。保留相机启动8帧预热、8 ms曝光、标定、模型、五候选筛选、前两名各三帧确认及原评分阈值。每轮重新初测，不复用上一轮频率。识别不明确则恢复100 Hz、100 μs快降脉冲，成功则保持所选正弦输出。

2026-10-31实机连续三轮，未输入真实频率作为模型条件：

| 轮次 | 收到测量指令后耗时 | 结果 | 33.3 kHz三张评分（越低越清晰） |
|---|---:|---|---|
| 1 | 3.764 s | 未通过确认 | 0.988、1.012、0.056 |
| 2 | 3.431 s | 未通过确认 | 0.554、0.226、0.088 |
| 3 | 3.512 s | 选中33.3 kHz | 1.006、0.130、0.050 |

上述时间不含启动时约6.95秒依赖加载。对照原快速策略单轮，导入后6.049秒，选中33.3 kHz，三张评分0.101、0.092、0.091；含依赖启动共12.995秒。

首轮33.3 kHz刚切换后的图片仍接近填满矩形，后续同候选变成清晰窄椭圆，与清帧后等待不足相符。仅凭本实验不能区分相机缓冲、示波器刷新/余辉及输出切换各自的贡献。此结果支持继续研究采集时序，尚不足以替代原快速策略；不能将三轮中的一次通过当作准确率结论。

图片与JSON报告分别位于 artifacts/diagnostics/one_flush_two_stage_20261031_101648、101652、101655；对照位于 fast_two_stage_20261031_101720。新增3项测试覆盖恰好两次读帧、取第二帧、时间戳及读帧失败处理，全部通过。
