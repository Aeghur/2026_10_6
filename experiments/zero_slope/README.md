# 中央零线斜率实验

独立入口，不修改原控制器、原预处理、已有模型或 config.json。
正弦接 X，零回扫锯齿接 Y。在正弦零电压的中央竖线 x=c 附近，

    x = c + A sin(2π f t + φ)
    dy/dt = H fs
    f = H fs / (2π A |dy/dx|)

A 为正弦横向半幅，H 为完整锯齿上升段的像素高度，fs 为 ACK 扫描频率。
斜率绝对值与相位、重叠分支数量无关；合并、缺失和回扫亮线会妨碍提取。
中央带内使用逐列白段中心提出方向，避开中央合并区，再以 asin((x-c)/A) 坐标线性回归，修正有限宽度曲率。
此处不是生成整张正弦图像进行匹配。

## 流程

1. 按固定顺序使用 500、1000、2000、5000、10000、20000 Hz 六个探索窗口。
   可用 --scan-windows 显式指定其他列表；不随机打乱。
2. 拒绝填充率超过 62% 的图像及不可分辨的斜率。
3. 从分离的斜率簇生成 1000–100000 Hz、100 Hz 步进的候选区间。
4. 每个探索窗口测试排名前五候选。每个候选分别用 f 和 f/2 扫描，各拍两帧。
5. 用连续性跟踪主曲线，记录剩余分支，再检查约 1 / 2 周期。
   这是验证拍摄结果的曲线回归，不是搜索整幅重叠图。
6. 候选失败继续探索；找到形状支持集合后结束。保存全部照片、ACK、候选、拒绝原因。

运行（设备操作只在显式 --hardware 时发生）：

```bash
cd /home/radxa/vision_sorter
.venv/bin/python experiments/zero_slope/slope_experiment.py --hardware
```

默认曝光 8 ms、增益 0、上升锯齿 4 Vpp，结束保留最后一次输出。
输出位于 artifacts/diagnostics/zero_slope_<时间>/。

## 实验边界

H 目前采用观察到的图形纵向跨度，尚无独立完整上升段标定。
接近画布上下边缘会记录 possible_vertical_clipping；这种图像仍可用于探索候选，
但裁切可能使候选整体偏低。confirmed 始终为 false。
局部斜率的像素误差与线宽会覆盖多个相邻 100 Hz 档位；通过双窗口形状检查，
也不等于证明频率精确到 100 Hz。最终保留支持集合，不把首个通过者当唯一真值。
前五候选预算可能漏掉正确候选；有限窗口探索也不保证找到可观测图形。
该实验只验证测频，不进行测相。

验证：五项合成图测试包括单周期、非整数比五分支、填满拒绝、错误周期拒绝、
重叠图不能当单分支验证。历史实拍图只能提供离线证据，不能代表当前输入。


## 验证器第二版

取消“整行恰好一个白段比例必须 ≥88%”的前置拒绝。
在纵向两端各排除 6% 的回扫过渡区域后，使用二阶动态规划跟踪每行白段中心，
同时考虑前后走向连续性与线宽支持，不单独取最长白段。
短缺失可跨越，长缺失仍会拒绝。正弦回归使用稳健迭代，明确记录被排除点。

多出来的白段单独统计：超过 20% 行存在未解释的远处分支时拒绝。
若剩余点至少 80% 能由一条直线解释，可标记为“类似回扫的直线残迹”。
这只是几何分类，不能据此证明该分支物理上必为回扫。

要求主曲线拟合内点覆盖检查区间至少 80%，归一化误差小于 3.5%，
拟合振幅与图形跨度相符，且无长缺失。周期形状容差从 2.5% 放宽到 5%，
原因是观察高度未独立标定且可能裁切；通过结果仍是粗形状支持，confirmed=false。
不应将放宽容差解释为达到 100 Hz 精度。

每张验证图附带 *_tracked.png（绿色主曲线点），完整轨迹和残余指标在 summary.json。
测试含回扫直线、短杂线、长缺失、第二条正弦，以及此前的单周期/重叠图用例，共九项。


## 局部斜率第二版

取消局部提取前的整图边界否决；横向振幅/中心由纵向内部区域的稳健分位数估计，
顶部横线不会直接改变主体横向边界。边界接触只记录标志，不等同于没有可用局部点。
局部提取不使用整图填充率否决，而是检查测点附近的填充、拟合残差和支持跨度。
上下各 6% 暂不测量，逐列白段中心保留交点两侧方向，避开中间 24% 半幅的合并区。
斜率测量范围扩至约 48% 半幅，避免只依赖几像素纵向差。
去重后保留多个穿越点和不同频率簇，不宣称所有局部点均已消歧。
完整锯齿高度仍是观察跨度假设，所有候选均不代表已校准的最终频率。

新增三项测试：顶端横线不否决内部测点、边界接触仅记录、局部遮挡保留其他点。
现共 12 项测试。对最近保存的 5/10/20 kHz 图均已能提取多个局部点；
候选仍有分歧，不能把“可提取”当作“频率正确”。新信号需进行新的硬件验证。
